Dark mode is the .dark class via shadcn's @custom-variant dark (&:is(.dark *)), which also allows scoped theming since the class need only be on an ancestor. Prevents ~40 dark: utilities across the generated components silently never firing, which is what forcing data-theme without redefining the custom-variant would have caused
- (decision) AD-36 arbitrary values are forbidden by eslint-plugin-tailwindcss 4.4.0 rule no-arbitrary-value, scoped off for components/ui/**. Verified: it correctly ignores arbitrary VARIANTS (data-[state=open]:, [&>svg]:size-4) which shadcn generates heavily, but flags real arbitrary values including inside cn() and template literals. The rule has an empty options schema so there is no allowlist - vendored shadcn primitives ship genuine arbitrary values by design and must be exempted by path
- (note) Token collisions to resolve in Story 1.2: shadcn's --color-accent is a muted SURFACE, not a brand accent, and collides with Nocturne's blurple; shadcn derives --radius-sm..4xl by calc from a single --radius, colliding with Nocturne's --radius-sm/md/lg. The clean adapter keeps shadcn's semantic @theme inline block untouched and repoints only its raw :root/.dark layer at the Nocturne scale, because components only ever name the semantic role. shadcn itself becomes a runtime dependency - globals.css imports shadcn/tailwind.css
